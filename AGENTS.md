## Project rules

- Component props: a component's own props type is named `Props` (`type Props = { … }`, then `({ … }: Props)`), never `<Component>Props` or an inline type annotation. This includes Next's generated types: `type Props = LayoutProps<"/[lang]">;` / `type Props = PageProps<"/[lang]">;`, then `({ … }: Props)`. One component with its own props per file. Only vendored shadcn primitives (`components/ui`) keep their upstream typing.
- Imports: always absolute with the `@/` alias (maps to the project root, e.g. `@/components/ui/button`, `@/lib/utils`). Never relative.
- Package manager: pnpm. TypeScript 7 (native compiler).
- Lint & format: Biome (`biome.json`), no ESLint/Prettier. `pnpm lint` checks, `pnpm format` writes fixes (format, Tailwind class order, import order), `pnpm typecheck` runs tsc. Markdown is not formatted.
- Database: Prisma 7 + SQLite through the libSQL adapter (`@/lib/prisma`). Generated client in `generated/prisma` (git-ignored, rebuilt on `postinstall`). Env vars: `DATABASE_URL`, `DATABASE_AUTH_TOKEN` (Turso only).
- Theme: neo-brutalist. Colors come from CSS variables in `app/globals.css`; the per-language palette is set with `data-lang="en|es"`, dark mode with the `.dark` class. Use `border-ink`, `shadow-brutal*`, `font-heading` instead of hard-coded values.
- Content: the card catalog lives in `content/<lang>/<deck-slug>.json` (format and validation in `@/lib/content/deck-schema`), languages in `@/lib/languages`. `pnpm cards:import` (or `--dry-run`) upserts it idempotently; card key = `<lang>/<deck>/<id or slug(term)>`, so renaming a `term` needs an explicit `id` to keep user progress. Cards removed from a file are reported, never deleted.
- Assets: static images live in `assets/` (e.g. `assets/svg/flags/<iso-3166-country>.svg`), statically imported and rendered with `next/image` (Next serves SVGs unoptimized, as-is, with a hashed cache-busting URL). `public/` is only for files that need a fixed URL (favicon, manifest, robots).
- Auth: Clerk (Core 3, `@clerk/nextjs` 7). `proxy.ts` only attaches the session; access control is resource-based: every server path reading user data calls `requireUser()` (`@/lib/auth/current-user`), which redirects to `/sign-in` and lazily upserts the `User` row (id = Clerk user id). Env vars: `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`. Clerk UI is skinned in `@/lib/auth/appearance` (CSS layer `clerk`, below Tailwind utilities). With Cache Components, Clerk components that read the URL must be wrapped in `<Suspense>`.
- Env files: secrets in `.env.local` (git-ignored). Next.js loads it natively; Node scripts and the Prisma CLI load `.env.local` then `.env` via `@/lib/load-env` / `prisma.config.ts`. Import `@/lib/load-env` FIRST in scripts (ESM imports run before the module body).
- Testing auth: the Claude desktop in-app browser drops Clerk's `__client_uat` cookie, which makes the page reload in a loop after sign-in. Test signed-in flows in a regular browser.
- Root layouts: there is no `app/layout.tsx`. `app/(global)/layout.tsx` (English: `/`, `/languages`, auth pages) and `app/[lang]/layout.tsx` (the studied language) each render `<RootDocument lang>` (`@/components/root-document`), so `<html lang>` is right on every page (WCAG 3.1.1). Navigating between the two roots is a full page load. `app/global-not-found.tsx` (flag `experimental.globalNotFound`) is the 404 for unmatched URLs; `app/[lang]/not-found.tsx` the one for `notFound()` under a language — never call `notFound()` in a root layout (Next falls back to its bare default 404).
- Signed-in areas are wrapped in `<Protected>` (`@/components/auth/protected` = Suspense + `UserGate`), so nothing renders before `requireUser()` passes. Pages under `[lang]` validate the language BEFORE their own `<Suspense>` (real 404 status) and stream their data inside it (instant navigation with Cache Components). Code reading the current time calls `await connection()` first. Auth URLs come from `@/lib/auth/routes` (used by both `proxy.ts` and `<ClerkProvider>`).
- Routes: `/` reopens `User.lastLanguageCode` or redirects to `/languages` (picker). `/[lang]` (`en`, `es`, prerendered via `generateStaticParams`) validates the segment with `languageFromParam` (404 otherwise), sets `data-lang` on its subtree (flag palette) and records the last language. URL helpers live in `@/lib/language-route`.
- Never set `prefetch={true}` on links to `/[lang]`: its layout records the last language during render (`RememberLanguage`), so a full prefetch would save languages the user never opened.
- Language of parts (WCAG 3.1.2): the document is `lang="en"`; any text in the target language (card terms, examples) must carry `lang={language.code}`.
- Navigation: tabs are configured once in `@/lib/navigation/tabs` (`built: false` = shown but not clickable, no dead links); `TabBar` renders them as a bottom bar on mobile and a sidebar from `md`. Counters (inbox, due, streak + week) come from `getLanguageStats` (`@/lib/stats/language-stats`, cached per request). Days are computed in the user's timezone with `@/lib/dates` (`LocalDay` = "YYYY-MM-DD").
- UI language: inside `/[lang]` the interface speaks the language studied (immersion). Every user-facing string comes from the typed dictionaries (`@/lib/i18n/dictionaries/<code>.ts`, `en.ts` is the source of the `Dictionary` type; `getDictionary(code)` in server and client components); counts use `pluralize(locale)` (Intl.PluralRules), dates `Intl` with `language.ttsLocale`. The `[lang]` wrapper sets `lang={code}`. `/languages` and the auth pages stay in English. Clerk's own UI (user menu, sign-in) is not localized yet.
- Review direction: a user setting (`User.reviewDirection`, `FORWARD` = target language → native, default), switchable anytime. A learned card has ONE `ReviewState` (`UserCard.reviewState`), whatever the direction: one card = one review, and switching direction keeps the schedule. Each `ReviewLog` records the direction used for that answer.
- Inbox (`/[lang]/inbox`): every card the user can see (`visibleCards` in `@/lib/cards/visibility`, shared by counters, lists and actions) and has no `UserCard` for is in the Inbox. Two lists, `?view=skipped`, `?deck=<slug>` and `?page=<n>` (`inboxHref`, `@/lib/inbox/views`). Pages hold `INBOX_PAGE_SIZE` (50) cards, which is also the most the action accepts at once: "Select all" ticks one page. Cards are unticked by default; decisions go through one server action (`sortInboxCards`, `@/lib/inbox/actions`), validated per list (`INBOX_MOVES`): new → learn (`UserCard` LEARNING, `discoveredAt` null = discovery to do) or skip (SKIPPED); skipped → learn or restore (row deleted = back in the Inbox). The action re-checks visibility, returns `{ ok: false }` for an invalid request (never a fake "0 moved") and ends with `refresh()`.
- Checkboxes: Base UI's `Checkbox` is a `<span role="checkbox">`, so a wrapping `<label>` only names its hidden input: give it `aria-labelledby`. Biome knows it as a control (`noLabelWithoutControl.inputComponents`).
